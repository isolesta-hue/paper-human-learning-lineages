# 재현 계획과 비교 기준 점검표 (Reproduction plan and baselines)

원칙: 글의 모든 숫자는 **결과 캐시에서 다시 만들 수 있어야** 한다. 새로 돌리지 않고 캐시를 읽어 표를 다시 내는 스크립트 하나(`make_tables.py`, 아직 없음)를
공개 사본에 둔다. 아래는 발견 → 그 숫자를 만든 실행 파일(원본: Helix Gold 저장소, 이름은 원본 그대로).

| 글의 절 | 발견 | 실행 파일 | 시드 |
|---|---|---|---|
| 5.1 완성 기준 / 5.2 다시 찾아내기 | F 103 | `run_rediscover.py`, `run_rediscover100.py` | 30 → 100 |
| 모드 | F 104 | `run_bundle.py` | 30 |

## 2. 해야 할 일
- [ ] 캐시 목록과 해시 기록(`cache*/` — 어떤 캐시가 어떤 표를 만드는지)
- [ ] `make_tables.py`: 캐시 → 글의 표 1~4, 그림 1~3 (새 실행 없이)
- [ ] 무작위 시드 하나로 처음부터 다시 돌려 캐시와 같은 숫자가 나오는지(회귀 확인과 같은 방식) 표기
- [ ] 의존성: 파이썬·PyTorch 버전 고정(`requirements.txt`), CPU 4개 기준 실행 시간 표

## 3. 비교 기준 (바깥 기준선) — 아직 없는 것
- [ ] 같은 세상에서 **크기를 맞춘 MLP**(문맥 낱말 주머니 → 답 낱말), 같은 회차·같은 복습
- [ ] 작은 트랜스포머: Helix Teal가 일부 덮음(F 73·76) — 크기 맞춘 표로 정리
- [ ] 빈도 기준선(가장 흔한 답), 무작위 기준선
- [ ] 모든 기준선에 같은 바깥 시험(처음 듣는 조합, 한 번 들은 짝, 옛 범주)
- [ ] 방법 층을 일반 하이퍼파라미터 탐색(무작위 탐색, 연속 절반 고르기만)으로 바꾼 대조 — "자기 판정"의 몫을 따로 보이기 위함

## 4. 하지 않을 것
- 원본 저장소를 통째로 공개하지 않음(대화 기록·세션 주소 포함) — 공개 사본만 정리해서.
